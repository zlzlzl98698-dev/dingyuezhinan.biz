Clash Verge Rev 在安装或启用服务模式（Service Mode）时提示权限不足，根本原因在于创建系统级后台服务和加载 TUN 虚拟网卡驱动必须通过操作系统的最高权限校验，而这一过程常被非管理员账户权限、安全软件主动防御拦截、中文安装路径解析异常或旧版残留服务占用所阻断。最快解决方式是以管理员身份运行客户端或把软件移至纯英文无空格路径，先彻底卸载并清理系统内残留的旧版 Verge 服务，临时放行安全软件对服务注册的拦截后重新点击安装。

很多用户刚从旧版桌面端迁移过来，容易混淆“系统代理”和“服务模式”两个概念。系统代理只是向操作系统写入一个本地监听端口地址，普通用户权限就能完成；而服务模式的作用是在系统后台注册一个以高权限常驻的系统服务，专门用来在启动 TUN 模式时拉起虚拟网络适配器，避免每次切换开关都弹出提权窗口。关于两者在日常使用中的差异，可以配合阅读 [TUN 模式异常排查](/troubleshooting/tun-error/) 与 [Clash Verge Rev 客户端说明](/clients/clash-verge-rev/)。

## 服务模式安装报错的四大常见诱因

在实际排错中，提示权限不足或拒绝访问并不总是单纯因为忘记右键管理员运行。按照触发频率排序，以下四个环节最容易卡住安装流程。

| 故障诱因 | 典型报错表现 | 核心处理动作 |
| :--- | :--- | :--- |
| 当前账户或进程权限不足 | 弹出 UAC 取消或直接提示 Access Denied | 完全退出程序后右键以管理员身份启动一次 |
| 安全软件阻断服务写入 | 安装进度条卡住或报服务启动超时 | 暂时关闭第三方杀毒软件的主动防御与驱动保护 |
| 安装或解压路径不规范 | 服务注册成功但核心无法启动或路径异常 | 迁移至 `C:\Tools\ClashVerge` 等纯英文路径 |
| 旧版或衍生版服务残留 | 提示服务已存在、端口被占或无法覆盖安装 | 通过管理员命令行删除旧服务后再重新安装 |

## Windows 平台分步排查与修复流程

Windows 10 与 Windows 11 的 UAC 用户账户控制和安全中心对底层服务注册管控较严，建议按顺序逐项排除。

### 第一步 彻底退出主程序并清理托盘驻留进程

很多用户只是点了右上角关闭按钮，软件其实仍最小化留在右下角系统托盘里。必须右键托盘图标选择“退出”，或者打开任务管理器确认 `clash-verge.exe`、`verge-mihomo.exe` 以及 `clash-verge-service.exe` 均已完全结束。如果不先结束后台驻留的核心进程，后续无论是覆盖安装还是提权运行都会被旧进程锁住权限。

### 第二步 使用管理员权限手动清理残留系统服务

如果你之前装过原版 Clash Verge、Clash for Windows 或其他采用同名后台服务的衍生分支，系统服务列表里往往还留着指向旧目录的服务记录。当新版本尝试注册服务时，就会因为无权覆盖旧服务句柄而提示权限不足。

右键点击 Windows 开始菜单，选择“终端（管理员）”或“命令提示符（管理员）”，依次执行查询与清理命令。

```powershell
sc query clash_verge_service
sc stop clash_verge_service
sc delete clash_verge_service
```

执行完成后如果系统提示“指定服务未安装”或者返回删除成功，说明原有冲突已经解除。注意部分早期版本服务名称可能包含连字符（如 `clash-verge-service`），可以通过 `services.msc` 打开系统服务管理窗口，在列表里按名称排序查找带有 Clash 或 Verge 字样的条目并核对可执行文件路径，确认无效后同样用命令行清除。

### 第三步 核对安装目录与安全软件拦截状态

便携版用户如果把压缩包直接解压在桌面上（路径往往包含中文用户名或 `Desktop` 空格），或者放在受系统严格保护的 `Program Files` 受限子目录中，服务进程在提权读取核心二进制文件时极易遭遇权限拒绝。推荐将安装版或便携版统一部署在纯英文、无特殊符号的独立目录下，例如 `D:\Apps\ClashVergeRev\`。

同时检查电脑上是否安装了第三方安全管家或杀毒软件。这类软件的“系统服务保护”与“驱动防火墙”规则，经常会在不弹出明显提醒的情况下直接拦截未知开源软件调用 `sc create` 注册系统服务。在重新安装服务模式前，建议临时暂停第三方安全软件保护，或者将整个 Clash Verge Rev 安装目录及内核文件添加至白名单信任区。如果是 Windows 自带安全中心误报隔离了 `clash-verge-service.exe`，需要前往“病毒和威胁防护”的保护历史记录里手动选择“还原”。

### 第四步 以管理员身份触发单次服务安装

完成上述清理后，找到 Clash Verge Rev 主程序图标，右键选择“以管理员身份运行”。进入设置页面，点击服务模式旁边的安装按钮。安装成功且状态显示为已运行（Active）之后，今后日常开机自启或手动启动就不再需要每次都用管理员权限运行客户端，普通用户权限下也能顺畅开关 TUN 模式。如果客户端本身出现启动闪退，可以对照 [客户端无法启动排查](/troubleshooting/client-wont-start/)。

## macOS 与 Linux 平台权限不足的处理差异

虽然权限提示在 Windows 上出现最多，macOS 与 Linux 用户在开启 TUN 模式时同样会碰到类似的系统授权限制。

### macOS 系统授权与密码输入要求

在 macOS 上，Clash Verge Rev 依靠系统自带的提权框架（osascript）向用户请求安装辅助服务或直接给 `verge-mihomo` 二进制文件赋予 root 权限以创建 `utun` 虚拟网卡。如果你在弹窗提示输入 Mac 开机密码时误点了取消，或者当前登录的 macOS 账号属于“标准用户”而非“管理员”分组，安装过程就会立即中断并报错。

解决方式是先确认当前账户具备管理员身份，然后在 Clash Verge Rev 中点击重新安装服务并完整输入开机密码（注意部分老旧设备开启了指纹解锁但提权脚本仍要求输入字符密码）。此外，切勿把 `.app` 文件留在“下载”目录或直接挂载在 `.dmg` 镜像窗口里双击运行，必须先拖入“应用程序（Applications）”文件夹中再启动，否则系统的门禁隔离机制（Gatekeeper）会剥夺它修改系统网络服务的权限。关于苹果电脑的架构与安装细节，可查阅 [macOS 客户端指南](/clients/macos/)。

### Linux 桌面端的内核权限授予

Linux 用户通过 `.deb`、`.rpm` 或 `.AppImage` 运行 Clash Verge Rev 时，服务模式失败多半是因为当前非 root 账户缺少创建 TUN 设备和配置网络能力的权限（`CAP_NET_ADMIN`）。除了采用官方推荐的服务安装脚本外，也可以使用 `setcap` 命令为内置的 Mihomo 核心二进制文件单独授予网络管理能力，或者确认系统已安装并启动 `systemd` 服务管理框架。对于使用 `AppImage` 格式的用户，由于每次运行都会挂载到临时只读目录，部分发行版无法持久保留服务路径，建议优先改用 `.deb` 或 `.rpm` 系统安装包。详细包格式区别见 [Linux 客户端专题](/clients/linux/)。

## 安装服务模式失败时的临时替代方案

如果因为处于公司受控电脑环境，个人账号确实没有任何本地管理员权限，无法安装系统服务也无法启用 TUN 模式，依然有合规的日常可用方案。

最稳妥的做法是关闭 TUN 模式，仅开启 Clash Verge Rev 的“系统代理（System Proxy）”。此时浏览器和绝大多数主流软件都可以直接走代理通道。对于命令行终端（如 Git、npm、pip 或 curl）这类默认不读取图形界面系统代理的工具，只需要在终端窗口里手动设置一次 `http_proxy` 与 `https_proxy` 环境变量，指向 Clash Verge Rev 默认监听的混合端口（通常为 `127.0.0.1:7897`），即可在无管理员权限的情况下正常拉取海外代码库。需要进一步排查连接失败或端口占用问题，可参考 [连接不上排查指南](/troubleshooting/connection-failed/) 与 [安全下载安装规范](/guides/client-install/)。
