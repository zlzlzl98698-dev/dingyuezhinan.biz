Shadowrocket（小火箭）在日常使用中，开启“配置（规则分流）”模式通常比“全局代理（Proxy）”模式更省电且发热量更低。虽然规则模式需要对每一次网络请求的域名或目标 IP 进行一次本地规则匹配，但这点算力消耗微乎其微；相比之下，全局代理强制把微信消息、国内视频流、网盘同步以及系统推送全部塞进加密隧道绕行境外服务器，不仅让手机基带维持大量远程长连接、大幅提高加解密运算负荷，而且在弱网环境下反复断线重连更会引发明显的额外掉电。

很多 iOS 用户误以为“不做分流直接全局转发”逻辑最简单所以更省电，实际结果恰恰相反。要看清两种模式在 iPhone 上的真实功耗差异，需要结合 iOS 系统底层的 Network Extension 机制以及不同流量类型的运行特征来分析。关于 Shadowrocket 的获取渠道、系统要求与基础功能定位，可先参考 [Shadowrocket 客户端档案](/clients/shadowrocket/) 与 [iOS 客户端汇总](/clients/ios/)。

## iOS 系统代理机制下的耗电来源拆解

在 iPhone 上，无论任何代理客户端都必须运行在苹果严格的沙盒与 Network Extension（网络扩展）内存限制框架内。只要右上角状态栏出现了 VPN 图标，就意味着系统内所有出站数据包都会先经过一个虚拟接口交给 Shadowrocket 后台进程处理。因此，真正的电量消耗主要来自以下四个环节。

| 功耗产生环节 | 配置（规则分流）模式表现 | 全局代理（Proxy）模式表现 |
| :--- | :--- | :--- |
| 数据加密与协议封装 | 仅海外流量走 TLS 与代理协议加密，国产应用直连零封装 | 100% 流量均需本地 CPU 进行加密运算与封包 |
| 射频与长连接维持 | 国内推送与即时通讯走直连基站链路，心跳稳定 | 全部后台推送被迫穿过代理隧道，跨网抖动时高频重连 |
| DNS 查询与往返耗时 | 境内域名走本地快速解析，延迟低，射频收发窗口短 | 全部解析等待远端返回，网络请求长时间挂起唤醒屏幕 |
| 规则匹配算力开销 | 每次新建连接遍历本地规则表，占用极少微秒级 CPU | 不走规则过滤，但单连接后续维护成本极高 |

举一个日常最典型的场景，当你打开国内短视频、听音乐或者用网盘备份相册时，单小时会产生数 GB 的并发数据流。如果处于全局代理模式，iPhone 的处理器必须一边解码高清视频，一边对每一帧流量进行高强度加密打包，同时机场节点的出口带宽往返延迟也会延长手机 5G 或 Wi-Fi 射频模块处于高功率发射状态的时间，结果就是机身背面迅速温热，电量百分比肉眼可见地下降。切换为规则分流后，国内视频和网盘流量被 `FINAL` 或 `GEOIP,CN,DIRECT` 规则直接放行，完全不经过加密隧道和节点中转，既省下了手机电量，也省下了机场的月度套餐流量。详细分流原理可阅读 [分流规则深度解析](/guides/routing-rules/)。

## 四类会导致规则模式也异常费电的错误设置

尽管规则分流在原理上比全局更省电，但如果配置文件写得过于臃肿或者开启了多余的监控功能，小火箭同样会出现异常耗电的情况。排查以下四项设置能进一步压低后台电量占比。

### 第一步 清理超大规模冗余广告过滤规则

许多用户喜欢从网上直接导入几万行甚至十几万行的“去广告、隐私拦截全能大杂烩配置文件”。Shadowrocket 的规则引擎在匹配大量带有复杂通配符或正则表达式的规则时，内存占用会迅速逼近 iOS 系统给 Network Extension 划定的上限（通常仅有几十 MB），不仅容易触发内存溢出断流，还会在并发打开网页时拉高 CPU 瞬间占用率。日常使用建议优先选择机场自带的精简分流配置，或者社区维护良好的轻量规则集，把不必要的巨型屏蔽清单精简掉。

### 第二步 关闭无用的流量日志与数据包捕获

在 Shadowrocket 的“数据”或“日志”相关页面中，如果长期开启“记录请求日志”或抓包调试功能，软件每处理一条连接都要在后台执行一次磁盘 I/O 写入操作。调试完毕后务必确认关闭抓包开关，只在排查具体某个 App 走直连还是走代理时临时打开一两分钟即可。

### 第三步 检查后台自动测速与连通性探测频率

在全局设置或节点分组设置里，如果把测速方式设成了极短间隔的循环延迟测试，或者频繁后台批量更新订阅，都会在锁屏间隙不停唤醒无线网卡。保持手动点击测速，或者仅在切换网络时按需刷新一次，能够显著减少待机耗电。

### 第四步 警惕部分流氓应用导致的直连或代理死循环

有些本地 App 会把某个埋点域名拼命向境外或错误地址高频重发，一旦该域名正好落在了失效节点或者屏蔽列表里，应用就会每毫秒重新发起一次连接请求，把小火箭进程彻底拖入高负载状态。如果发现电池统计里 Shadowrocket 后台耗电突然飙升，可以临时打开几秒钟日志列表，一眼就能看出是哪款 App 在后台疯狂刷屏重连，将其单独屏蔽或调整分流策略即可。

## 全局代理的合理适用时机与切换建议

既然全局代理更费电还浪费流量，它存在的意义主要是应对规则库尚未覆盖的特殊突发场景。

当遇到某个冷门海外学术站点、新上线的小众 AI 工具界面打不开，或者某些国外游戏服务端域名没被写进规则列表导致加载卡死时，可以临时在主界面把全局路由从“配置”切换为“代理”，验证是不是分流规则漏判所致。一旦确认打开正常，长期使用建议把该域名手动添加到自定义规则列表中指向代理分组，然后重新把全局路由切回“配置”。

对于同时持有大量国内常用软件和少数海外工作软件的用户，还可以利用好 Shadowrocket 的分流精细度，把长期不需要出境的大流量影音应用通过 `DIRECT` 规则固定在本地直连通道。如果遇到切换模式后依然全节点不通或耗电异常，可以进一步对比检查 [节点全部超时排查](/troubleshooting/node-timeout/) 与 [流量消耗异常分析](/troubleshooting/abnormal-traffic/)，避免被失效节点空转消耗电池。
