Shadowrocket 添加订阅后节点全部超时，绝大多数情况都逃不出五个常见原因，分别是系统时间存在明显偏差导致握手校验失败、机场套餐流量耗尽或订阅已过期、小火箭版本号过旧无法兼容机场下发的新传输协议、本地测速方式误报或网络环境阻断了节点端口，以及机场节点本身遭遇阶段性维护或入口域名失效。排查时建议先核对手机系统时间与机场后台剩余流量，随后把连通性测试方法改用 URL 响应测试并确认客户端已升级至最新版，通常就能快速找出真实病灶。

很多用户在小火箭刚导入订阅时，看到一整排节点延迟测试结果全是一片红色“超时”，第一反应是机场已经跑路或者彻底坏了。实际上在移动网络和苹果系统生态下，假超时和本地环境卡壳占比极高。如需先核实软件的官方商店版本和适用协议支持情况，可参考 [Shadowrocket 客户端说明](/clients/shadowrocket/) 与 [全节点不可用排查框架](/troubleshooting/all-nodes-down/)。

## 原因一 手机系统时间未自动同步引发 TLS 鉴权失败

无论你的机场底层采用的是 VMess、Trojan、VLESS Reality 还是 Hysteria 2，现代代理协议高度依赖 TLS 安全握手与时间戳验证机制来抵御重放攻击。如果 iPhone 或 iPad 的系统时间与世界标准时间偏差超过六十秒到九十秒（例如为了某些游戏调改过手机日期、或者长期关掉自动设置时间后产生走时漂移），几乎所有加密节点都会在握手阶段被服务端直接拒绝丢弃，客户端表现出来就是所有节点同步报超时。

排查这一项只需要短短十秒。进入 iPhone 的“设置”中的“通用”菜单，打开“日期与时间”，确认“自动设置”开关处于开启状态，并且时区正确识别为当前所在地。如果原本就是开启状态但怀疑时钟不准，可以先关闭开关再重新打开，强制手机通过网络校准时间后再回到 Shadowrocket 重新测速。

## 原因二 机场套餐过期、流量归零或超出并发设备数

机场下发订阅链接后，节点列表并不会随着你的套餐到期而自动清空，很多面板在用户流量耗尽或套餐到期后，依然允许拉取一份包含所有节点地址的配置文件，但在服务端网关处会直接拦截该账户 UUID 的转发流量。同样，部分低价机场对同时在线 IP 数或设备数限制较严，一旦家里路由器、电脑和手机叠加超过了允许上限，后台风控系统可能会短暂冻结该用户的连接权限，此时在手机端就会看到全部节点同时超时。

验证方法很简单，打开手机浏览器登录机场的官网控制面板（不要挂代理直连备用入口域名），重点查看账户首页的三项状态，当前套餐是否仍在有效期内、本月已用流量是否触及 100% 上限、以及后台有没有提示设备数超限或账号异常公告。确认流量充足且状态正常后，回到小火箭对订阅条目左滑点击“更新”，确保拿到最新的节点接入域名和端口。关于流量消耗过快与订阅状态的核对方式，可参考 [流量消耗异常排查](/troubleshooting/abnormal-traffic/)。

## 原因三 小火箭版本过旧不兼容现代新协议

目前主流机场为了优化跨网传输稳定性和抗阻断能力，已经广泛部署了 VLESS Reality、Hysteria 2、AnyTLS 等新一代协议。这些新协议需要客户端具备相匹配的底层加密库与握手机制支持。如果手机里安装的 Shadowrocket 是早年通过非正常渠道或者一次性借用他人旧账户下载且长期未更新的陈旧版本，不仅解析节点参数时可能丢失关键字段（如 `pbk` 公钥或 `sni` 伪装域名），在实际连接时也会直接因为协议不匹配而全部超时。

必须强调一个重要的安全规范，中国区 App Store 无法搜索和下载 Shadowrocket，部分用户图方便在电商平台购买低价“共享 Apple ID”安装后就再也没更新过，或者被商家要求在“设置”里登录共享账号。这种做法不仅会导致软件版本长期停滞无法适配新协议，更隐藏着极高的“iCloud 锁机勒索”风险。正确的解决方式是用自己长期可控的海外地区 Apple ID 在 App Store 正规购买并升级到最新版本，或者改用官方免费上架的跨平台替代品如 [Karing](/clients/karing/)。关于安全与风控底线，可阅读 [机场与客户端安全性指南](/risks/security/)。

## 原因四 测速方式误判与本地网络环境阻断

不少用户碰到的其实是“假超时”，或者是当前所处的 Wi-Fi 出口环境拦截了代理端口。

| 异常情境 | 表现特征 | 建议处理动作 |
| :--- | :--- | :--- |
| 连通性测试方法选成 TCP 误判 | 测速全红，但直接打开海外网页却能秒开 | 进入小火箭设置把测速模式改为 URL 测试 |
| 校园网、企业内网或公共 Wi-Fi 拦截 | 连公司 Wi-Fi 全超时，切回手机 5G 流量立刻全绿 | 避开限制苛刻的局域网环境，或尝试使用 443 端口节点 |
| 开启了手机自带低数据模式或异常 DNS | 无论连接哪个节点都无法建立初次域名解析 | 检查 Wi-Fi 详情里的 DNS 是否被改乱，关闭冲突的 VPN 配置 |
| 手机同时残留多款 VPN 描述文件 | 系统网络扩展被其他加速器抢占，数据包无处可去 | 进入 iPhone 设置中的 VPN 管理确认仅保留当前一项 |

进入 Shadowrocket 底部“设置”菜单，找到“延迟测试方法”。默认的 `TCP` 握手测试在面对部分禁止探测或者带多层中转的节点时很容易返回超时，把它切换为 `CONNECT`（URL 测试），测试地址填写常规无墙状态检查链接，通常能反映真实的网页可用性。此外，强烈建议在测试节点前，先断开当前 Wi-Fi 改用手机蜂窝移动网络（4G/5G）测一遍，这是区分“本地路由器防火墙问题”还是“机场真故障”最快的一刀切测试法。如果切换到移动网络后依然全部连接失败，可以进一步对照 [连接不上排查手册](/troubleshooting/connection-failed/) 与 [节点超时标准流程](/troubleshooting/node-timeout/)。

## 原因五 机场上游节点大面积维护或入口域名被墙

如果你已经排除前面四项本地问题，在蜂窝网络和 Wi-Fi 下更换测速方式依然全部无响应，且同订阅里所有地区（香港、日本、美国、新加坡）毫无例外全部超时，就要高度关注机场服务商自身的状态了。

很多中小型机场为了控制成本，会共租同一个上游中转机房入口域名。一旦在特殊网络波动期遭遇入口 IP 集体阻断或者中转机房机柜维护，用户手里之前拉取到的旧订阅节点就会瞬间全部失联。遇到这种全盘瘫痪，切勿停留在客户端里反复瞎调参数，正确做法是第一时间登录机场后台查看最新通知、工单或官方状态渠道确认是否在更换中转地址，同时点击一次“更新订阅”尝试拉取服务商刚换上的新入口 IP。如果机场连续多日失联且没有任何恢复公告，建议参考 [运营异常识别](/risks/operational-issues/) 及时做好备用方案准备。
