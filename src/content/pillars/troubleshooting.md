用代理最崩溃的瞬间，莫过于前一天还好好的，第二天早上打开电脑突然所有节点全部红字超时，或者更新订阅直接弹出一串英文报错。遇到这类故障，千万别上来就卸载重装客户端或者把机场骂一通，90% 的日常异常都出在五个可快速验证的环节上，按由近及远的顺序排一遍，通常三分钟就能恢复。

排查故障的核心思路是先隔离本地环境，再检查客户端配置，最后验证服务商入口。只要把“本地没断网、系统时间准确、套餐没欠费、内核版本够新”这四件事先确认完，剩下的问题范围就会缩得很小。

## 故障定位的边界划分，区分本地问题与上游波动

故障排查的第一步，是弄清问题出在自己设备上还是出在机场服务器那一端。判断标准非常简单。

如果浏览器在关闭系统代理后打不开国内网页，说明问题出在你的路由器、光猫或者宽带运营商，跟订阅和客户端毫无关系。如果关闭代理后国内网络飞快，只是一开代理就连不上外网，或者订阅更新卡死，再进一步区分是客户端软件没启动核心进程（常见表现为 [客户端无法启动](/troubleshooting/client-wont-start/) 或 [TUN 模式异常](/troubleshooting/tun-error/)），还是配置文件本身过期损坏。

反过来，如果同一份订阅链接在手机流量下能正常秒开网页，切回公司 Wi-Fi 或校园网就全部超时，那大概率是当前局域网防火墙拦截了特定端口或干扰了 DNS 解析，这属于典型的本地网络环境限制，光靠找机场客服换节点是解决不了的。

## 五步标准化排查顺序，不要跳步盲目重装

遇到异常时严格按以下五个层级推进，每通过一级就排除一大类原因，效率最高。

### 第一步核对账号状态与系统时钟

先登录机场官网用户中心（如主域名打不开可尝试官方发布的备用发布页），一眼确认两件事，剩余流量是不是已经扣到零了，以及当前套餐是否在有效期内。很多用户开了自动更新却忘了月末流量清零日还没到就把额度用光了，结果就是客户端里节点全绿却什么网页也打不开。

紧接着看一眼电脑右下角或手机的系统时间。现代加密代理协议（如 TLS、VLESS、Trojan）在握手校验时允许的时间偏差通常在几十秒以内。一旦主板电池没电或虚拟机休眠恢复导致系统时间差了几分钟，就会引发全线 [节点超时](/troubleshooting/node-timeout/)，打开系统设置的自动同步时间即可瞬间修复。

### 第二步检查订阅更新与客户端内核兼容

机场运维日常会定期更换受损入口域名或下线维护旧服务器。如果你连续一两个月没点过“更新订阅”，本地缓存的还是老地址，当然会连不上。更新订阅时要注意先关闭当前已经失效的全局代理，防止客户端尝试通过死掉的旧节点去拉取新配置。

如果更新时明确报错提示“格式错误”“不支持的协议”或节点导入后列表空白，多半是 [订阅更新错误](/troubleshooting/subscription-update-failed/) 或 [客户端兼容性问题](/troubleshooting/client-compatibility/)。近两年机场大面积切换到了 VLESS Reality、AnyTLS 与 Hysteria 2，老旧客户端（如已停更的原版 Clash for Windows 或旧版 Clash for Android）无法解析这些新字段，升级到基于 Mihomo 或 sing-box 的 Clash Verge Rev、FlClash、Karing 或新版 v2rayN 即可解决。

### 第三步隔离端口占用与 TUN 虚拟网卡冲突

有时客户端界面明明显示正常，网页却永远转圈无法建立连接，甚至同时开着两款加速器或公司 VPN 导致本地代理端口（如常见的 `7890`、`10808`）被抢占。此时需要参照 [连接不上](/troubleshooting/connection-failed/) 检查系统代理设置是否被其他软件篡改，或者退出冲突的网络加速工具。

开启 TUN 虚拟网卡模式后如果遇到“服务模式安装失败”“无法创建网卡”或者全机断网，应进入 [TUN 模式异常](/troubleshooting/tun-error/) 核查是不是缺少管理员权限、杀毒软件拦截了核心服务，或者与虚拟机网卡存在路由冲突。

### 第四步清理异常 DNS 缓存与局域网解析冲突

能连上节点、测速也正常，但访问某些特定网站一直打不开，或者内网 OA、NAS 地址突然失灵，九成是 [DNS 错误](/troubleshooting/dns-error/)。常见诱因是客户端开启了 Fake-IP 模式后异常强退，导致系统缓存里残留了 `198.18.x.x` 段的虚假解析记录。重启客户端或手动刷新系统 DNS 缓存，通常就能立刻恢复。

### 第五步复核流量异常与带宽瓶颈

发现流量莫名其妙一天掉了几十 GB，别急着怀疑商家偷跑，先按 [流量消耗异常](/troubleshooting/abnormal-traffic/) 的步骤核查三处地方，有没有误连了 3x 或 5x 高倍率节点、电脑后台的 OneDrive / iCloud / 网盘 / Steam 更新是不是正在走全球流量偷跑，以及你的订阅链接有没有泄漏。同样，遇到 [网络速度慢](/troubleshooting/slow-speed/) 时，要先对照不同地区节点和不同时段测速，分清是单一节点抽风、本地运营商晚高峰限速还是套餐自身带宽上限。

## 常见故障症状与快速定位索引表

下表对应了最常见的 11 种一线故障现象，遇到对应提示时可直接点击右侧专题按步骤操作。

| 界面报错或直观症状 | 高概率根因 | 第一时间自救动作 | 详细排查指南 |
| --- | --- | --- | --- |
| 全部节点测速红字超时 | 系统时间偏差、套餐到期、旧入口失效 | 同步系统时间、查官网流量、直连更新订阅 | [全部节点不可用](/troubleshooting/all-nodes-down/) |
| 单个或少数区域节点超时 | 该地区机房维护或单线运营商抖动 | 切换香港/日本/新加坡等其他可用节点 | [节点超时](/troubleshooting/node-timeout/) |
| 拉取订阅报错、链接打不开 | 代理套娃、订阅域名被本地 DNS 干扰 | 关掉代理重试、勾选通过代理更新或换备用域名 | [订阅失败](/troubleshooting/subscription-failed/) |
| 订阅更新成功但节点不显示或报错 | YAML 格式异常、客户端核心版本太旧 | 确认非网页 HTML 报错页面，升级到 Mihomo/sing-box 端 | [订阅更新错误](/troubleshooting/subscription-update-failed/) |
| 客户端打不开或启动闪退 | 端口占用、杀软误杀核心文件、系统缺权限 | 将核心目录加入杀软白名单、检查 `7890` 端口占用 | [客户端无法启动](/troubleshooting/client-wont-start/) |
| 开启后本地浏览器无法上网 | 系统代理端口残留、与游戏加速器或公司 VPN 冲突 | 关闭多余网络工具、核对系统代理端口是否一致 | [连接不上](/troubleshooting/connection-failed/) |
| 开启 TUN 模式报错或断网 | 未安装服务模式、无管理员权限、虚拟网卡冲突 | 右键以管理员身份安装 Service Mode 后重启软件 | [TUN 模式异常](/troubleshooting/tun-error/) |
| 网页转圈或内网设备访问异常 | Fake-IP 残留污染或 DNS 分流泄漏 | 刷新本地 DNS 缓存、切回 Redir-Host 测试或加直连例外 | [DNS 错误](/troubleshooting/dns-error/) |
| 套餐流量消耗远超日常预期 | 误用高倍率节点、后台网盘同步、订阅链接泄漏 | 检查节点倍率前缀、重置后台订阅地址并改密码 | [流量消耗异常](/troubleshooting/abnormal-traffic/) |
| 能连上但视频卡顿、测速极低 | 运营商晚高峰拥堵、单节点限速或本地 Wi-Fi 干扰 | 切换不同地区节点对比、避开高负载节点与高峰测试 | [网络速度慢](/troubleshooting/slow-speed/) |
| 导入新协议节点失败或报错 | 老旧软件不支持 VLESS Reality、AnyTLS 等新协议 | 更换 Clash Verge Rev、v2rayN 或 Karing 等活跃端 | [客户端兼容性问题](/troubleshooting/client-compatibility/) |

## 合规说明与排查后的止损选择

所有故障定位与参数调试指导均针对合法合规的网络环境与技术故障排错。修改系统代理、DNS 或虚拟网卡设置时，若涉及公司内网安全策略设备，请务必先与企业 IT 管理员确认，避免违规改动终端配置。

如果把上述五个层级全部排完，还是连续几天出现工单石沉大海、所有官网备用域名同时失联、节点全区长期归零的情况，说明问题已经超出技术排查范围，变成了服务商运营异常。这时不要继续等待，应立即前往 [风险与替代](/risks/) 查看止损预案与备选迁移清单。
