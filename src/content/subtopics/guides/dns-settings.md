即使你的机场节点速度和延迟表现都很理想，如果本地客户端的 DNS 解析配置出了偏差，依然会出现“点开网页先白屏卡住好几秒才能加载”、“国内网站突然打不开”或者“AI 工具提示所在地区不支持”等棘手状况。理解加密 DNS、Fake-IP 与 Redir-Host 的分工逻辑，能让你迅速避开大部分看不见的解析隐坑。

## 为什么代理软件必须自己管好 DNS

在普通宽带环境下，浏览器输入一个网址后，电脑会向宽带运营商默认分配的 DNS 服务器询问这个域名对应的真实 IP。一旦跨国访问，传统的明文 UDP DNS 查询很容易遭到中间链路抢答篡改（也就是常说的 DNS 污染），返回一个错误的虚假 IP，导致连接失败。

更微妙的问题在于国内分流效率。假如你的客户端为了安全，把所有域名的 DNS 请求全都一股脑丢给国外的节点服务器去查，那么当你打开淘宝、百度或国内网盘时，境外 DNS 服务器很可能会给你的电脑返回一个位于海外边缘 CDN 节点的 IP，或者导致国内流媒体加载速度大幅下滑。

因此，现代代理内核（如 [Mihomo](/clients/mihomo/) 和 [sing-box](/clients/sing-box/)）都内置了一套独立而精细的 DNS 分流路由器，做到“国内域名交给国内加密 DNS 快速拿就近 CDN 地址，海外域名防污染并且不泄漏给本地运营商”。

## Fake-IP 与 Redir-Host 的核心区别

在使用 Clash 生态或 OpenWrt 软路由组件时，DNS 设置中最核心的选择项就是 **enhanced-mode**，主要包含 Fake-IP 与 Redir-Host 两种工作模式。

### Fake-IP 模式（当前多数默认与首选）

在 Fake-IP 模式下，客户端拿到浏览器发来的域名解析询问时，根本不去耗费时间等待远程真实查询结果，而是瞬间从本地保留网段（通常是 `198.18.0.1/16`）里随手抽出一个虚假 IP 塞给浏览器，同时在内部小本子上记下“这个假 IP 对应的是哪个真实域名”。

紧接着浏览器带着这个假 IP 发起连接，流量一进入客户端，内核立刻通过小本子查回原始域名并对照规则表：如果是国内域名就让本地再去直连解析，如果是海外域名就把原始域名直接连同加密请求一起打包塞给境外机场节点，由远端海外服务器去就近解析真实目标 IP。

它的优点非常突出，响应速度极快，几乎省去了第一轮跨国 DNS 查询的往返耗时，也避免了远端节点返回奇怪的地理偏移 IP 造成访问异常，且天然杜绝了海外域名向本地发明文查询的泄漏风险。

### Redir-Host 模式（传统真实 IP 模式）

在 Redir-Host 模式下，客户端老老实实地按照正常逻辑，根据域名分流规则分别向配置的国内 DNS（如阿里、腾讯 DoH）或远程加密 DNS 发起真实查询，并把查到的真实海外服务器 IP 地址返还给系统程序。

这样做的好处是系统里拿到的全都是货真价实的公网 IP，对于某些需要自行校验 IP 归属、不支持假 IP 通信的特定游戏联机、远程开发调试或者极少数死板的本地老软件非常友好。缺点则是比 Fake-IP 多了一次解析等待耗时，且如果在配置中忘记打开真实加密远程解析，或某些软件绕过了系统分流，相对更容易出现缓慢或轻微泄漏。

## 正确配置与日常使用避坑提醒

如果机场下发的 Clash YAML 订阅文件里已经写好了完整的 DNS 配置区块，新手用户强烈建议直接沿用机场原配，不要盲目从网上找“万能极速 DNS 代码”整段替换进去。如果确实需要自行调整或用覆写修正故障，注意以下几个实用守则。

1. **不要用 Fake-IP 状态下系统的 Ping 延迟当作节点速度**。开启 Fake-IP 或 TUN 模式后，你在电脑命令行执行 `ping google.com` 看到显示的往往是 `198.18.0.x` 且延迟只有 1 毫秒，这测的只是你电脑到本机虚拟网卡之间的内存往返耗时，根本代表不了机场节点通往海外的真实延迟。要测节点真实连接质量，请在客户端内部界面使用 URL-Test 测试。
2. **防范软路由或系统的 Fake-IP 缓存残留**。部分设备开启 Fake-IP 后，如果你突然强制退出代理软件，浏览器或操作系统内部可能还短暂缓存着 `198.18.x.x` 这串无法独立出网的假地址，导致关掉代理后一段时间内打不开网页。正常规范退出软件、或者在系统命令行刷新一下 DNS 缓存即可立即恢复，具体修复流程可见 [DNS 错误排查](/troubleshooting/dns-error/)。
3. **浏览器安全 DNS（DoH）的抢占冲突**。Chrome、Edge 和 Firefox 现代浏览器经常默认开启“使用安全 DNS”选项，如果浏览器自己绕过系统设置的端口跑去直连公共 DoH，就有可能打乱客户端的 Fake-IP 规则或引发部分域名解析失败。当你在开启代理软件的同时频繁碰到莫名其妙的网页解析卡顿，可以尝试在浏览器隐私安全设置中先关闭浏览器自带的独立安全 DNS，统一交由代理客户端接管。
4. **确保系统 DNS 与上游通道分开**。配置自定义 DNS 时，国内直连组推荐搭配支持加密传输的阿里或腾讯 DoH，防止运营商劫持；代理节点组搭配海外加密 DoH 并明确经由代理通道发出。做好这两点，再用专业网速检测网页验证是否泄漏，基本能保证解析既迅速又干净。
