打开桌面端的 [Clash Verge Rev](/clients/clash-verge-rev/)、[v2rayN](/clients/v2rayn/) 或者手机端的 [Shadowrocket](/clients/shadowrocket/)，主界面最核心的调度开关永远围绕 `Rule`（规则模式）、`Global`（全局模式）与 `Direct`（直连模式）三种状态展开。对于绝大多数用户而言，日常 99% 的时间都应当稳稳固定在规则模式下运行，让客户端引擎自动把国内常用应用留在本地直连通道，仅将海外目标与 AI 工具送往节点转发；全局模式仅适合作为临时排查规则缺失或跨区强环境检验的短时诊断工具；直连模式则充当无需退软件即可对比排障的临时旁路开关。

## 三种运行模式的核心逻辑与客户段命名对照

不同开发体系的软件对这三种模式的文字翻译略有差别，但在底层路由调度上完全一一对应。下面这张对照表梳理了三者的实际运行差异。

| 对比维度 | Rule 规则模式 | Global 全局模式 | Direct 直连模式 |
|---|---|---|---|
| 路由匹配逻辑 | 逐条比对本地 Geosite、GeoIP 与域名规则表后分流 | 忽略绝大多数分流规则，直接送入总代理出口 | 停止转发给任何节点，全部请求直接走本地物理宽带 |
| 国内应用访问路径 | 直连本地宽带，不绕道海外机房 | 强行先到境外落地节点再折返回国内服务器 | 直连本地宽带，与未开代理时路径完全一致 |
| 机场订阅流量消耗 | 仅消耗海外目标流量，最节省月度配额 | 全部国内高清视频、软件更新与下载都会扣减流量 | 零机场流量消耗，仅消耗本地宽带与手机流量 |
| Clash 系面板命名 | 规则（Rule） | 全局（Global，需注意顶部的 `GLOBAL` 分组指向） | 直连（Direct） |
| Shadowrocket 命名 | 全局路由里的“配置” | 全局路由里的“代理” | 全局路由里的“直连” |
| v2rayN 与 v2rayNG | 路由预设“绕过局域网及大陆地址” | 路由预设“全局代理” | 路由预设“全局直连” |
| 日常使用建议 | 长期默认常驻开启 | 仅限排障测试或极少数要求全页海外 IP 的操作 | 怀疑客户端干扰国内业务或大文件下载时临时切换 |

## Rule 规则模式 日常使用的唯一标准形态

规则模式的核心价值在于让国内业务与海外业务各行其道，既保护节点流量不被无端浪费，又保证国内银行、社交与短视频软件保持原生态的低延迟体验。

开启规则模式之后，代理内核在收到每一条来自浏览器或应用软件的连接请求时，都会快速查询内置规则列表与数据库。

1. **国内与局域网目标走 `DIRECT`**。当你打开淘宝、微信、公司 OA 系统、本地网盘或者路由器后台网页时，请求匹配到国内域名库或内网保留网段后，立刻直接从本地网卡发出，既不会经过机场服务器增加几十毫秒延迟，也不会花掉套餐里的哪怕 1MB 流量。
2. **海外目标与特定服务走代理组**。当你访问海外学术网站、YouTube、Netflix、ChatGPT 或跨区电商平台时，内核识别到它们命中境外域名规则或兜底规则，自动将加密流量送往你选定的香港、日本或新加坡等节点转发。
3. **追踪脚本与已知广告走 `REJECT`**。部分机场下发的精细配置还包含拦截清单，在本地阶段就直接丢弃高风险追踪域名的请求。

要确保规则模式顺畅工作，除了规则本身准确，还需要配合干净的域名解析流程。如果发现打开某些国内服务莫名卡顿，或者海外网站虽然走了节点却始终慢半拍，通常需要进一步核查客户端的 [DNS 设置与防泄漏配置](/guides/dns-settings/)。

## Global 全局模式 不可常驻的临时诊断开关

很多刚接触代理工具的新手会陷入一个常见直觉误区，认为既然已经付费买了机场，干脆直接开 Global 全局模式让所有网页都走高级专线，岂不是省事又稳定。实际上，长期开启全局模式会同时带来两方面严重副作用。

### 国内应用卡顿与异地风控拦截

一旦进入全局模式，国内银行、支付工具与外卖地图应用发出的网络包全都被送去香港、日本或美国转了一圈再折返国内机房。不仅网盘下载和高清追剧速度大幅下滑，外卖、打车软件会因为出口 IP 落在境外而导致定位完全错乱，部分对账户安全敏感的金融和办公软件还会直接弹出异地风险警示甚至强制冻结会话。

### 机场流量配额被迅速刷干

日常观看几集国产高清连续剧、或者在后台让系统静默更新几个大型桌面软件安装包，动辄产生十几到几十 GB 的数据吞吐。在全局模式下，这些原本无需代理的数据全都要经过机场服务器并记入你的月度流量账本，极易导致套餐提前见底，这也是造成 [流量消耗异常](/troubleshooting/abnormal-traffic/) 的头号原因。

全局模式真正合理的使用场景只有两个。第一是**排除规则漏网之鱼**，当你在规则模式下发现某个冷门新上线的海外工具网页一直超时打不开时，先临时切到全局模式测试一分钟。如果全局下立刻秒开，就能明确问题出在规则库还没收录该域名，随后用覆写规则补充进去即可切回规则模式。第二是**极少数全页面同源环境校验**，某些严格校验注册环境的海外平台要求页面内嵌的全部第三方统计、静态字体与验证脚本都必须出自同一个海外 IP，操作完成后同样应立刻切回规则模式。

使用基于 Mihomo 的客户端切到 Global 模式时，务必顺手点开策略面板最上方新出现的 `GLOBAL` 总分组。检查里面选中的是不是你真正想用的海外节点，很多时候该分组默认停留在 `DIRECT`，结果导致表面显示开启了全局模式，实际上依然全部在走本地直连。

## Direct 直连模式 不关客户端的快捷旁路

切换为 Direct 直连模式时，代理软件依然保留在后台并维持本地监听端口或虚拟网卡通道，但内核不再把任何请求转交到远程代理服务器，而是统统改回本地宽带直出。

这个开关在排障与临时大流量作业时非常好用。例如当你怀疑某个国内办公内网打不开是因为机场配置规则冲突时，不用去系统设置里卸载或彻底杀死代理进程，直接切到 Direct 刷新网页就能在三秒内验证是不是分流规则导致的异常。此外，在下载几十 GB 的大型游戏安装包、同步本地大体积镜像文件，或者连接严格绑定本地物理 IP 的企业内网系统前，随手切到直连模式也能防止误走代理。

## 进阶实操 用 YAML 规则优先级修正漏网域名

如果你熟悉了 [Clash 配置知识](/guides/clash-config/)，遇到少数小众海外域名在 Rule 模式下被误判直连，或者某个国内新上线镜像站反而绕路走了代理，可以直接通过客户端的全局覆写往顶部追加精确规则。

Mihomo 与 Clash 内核严格按照文件**从上到下首次命中即停止**的顺序匹配规则。因此自己手动补充的例外域名必须插在机场默认规则之前，否则根本轮不到它生效。以下是一段标准的通用规则语法顺序示例，演示如何按进程、精确域名、后缀和国家代码分层匹配。

```yaml
prepend-rules:
  # 1. 按进程名称强制直连，适合大流量下载工具或特定内网软件
  - PROCESS-NAME,aria2c.exe,DIRECT
  # 2. 按完整域名精确指定出口，优先级高于泛后缀规则
  - DOMAIN,api.custom-tool.example.com,节点选择
  # 3. 按主域名后缀匹配旗下所有子域名
  - DOMAIN-SUFFIX,internal-corp.example.com,DIRECT
  # 4. 机场原配置通常在尾部保留常规兜底逻辑
  # - GEOSITE,cn,DIRECT
  # - GEOIP,CN,DIRECT,no-resolve
  # - MATCH,节点选择
```

需要注意，`PROCESS-NAME` 按进程名匹配规则在桌面端开启 [TUN 模式](/guides/tun-mode/) 或搭配系统代理时都能准确识别程序名称，但进程名在 Windows 与 macOS 上大小写和后缀略有差异（例如 Windows 带有 `.exe` 后缀）。对于跨平台通用的调整，优先使用 `DOMAIN` 或 `DOMAIN-SUFFIX` 更为稳妥可靠。

## 常见问题

### 日常上网长期开着 Global 全局模式会有什么问题？

第一，访问国内视频、网盘下载、银行和外卖平台也会绕道境外服务器再折返，导致国内软件打开卡顿甚至无法定位；第二，所有国内大流量下载都会被计入机场订阅配额，原本够用一年的流量可能几天就被刷光。

### 如果我在 Rule 规则模式下发现某个小众海外网站打不开，怎么办？

原因通常是该小众新域名还没有被收录进机场下发的规则列表中，被兜底判定走直连了。可以临时切到 Global 模式验证节点本身是否能打开它，确认有效后通过客户端自定义规则或覆写把该域名加入代理组即可。

### 为什么有时候选了 Global 模式，打开海外网站依然显示超时？

切到 Global 模式后，有些客户端（如 Clash 系）会在面板多出一个独立的 GLOBAL 总策略组。如果这个总策略组默认停留在了 DIRECT（直连）而不是你选的节点，即使开了 Global 模式流量一样不会走代理，需要手动进去指定出口节点。

### 在 Rule 模式下，明明访问的是国内网站为什么还是消耗了机场流量？

最常见的原因有三类，分别是某些国内网站加载了海外 CDN 资源触发代理命中、本地 DNS 污染导致国内域名解析出异常 IP 走错通道，或者用户在客户端规则顺序里把过宽泛的代理关键字排在了国内规则前面。
