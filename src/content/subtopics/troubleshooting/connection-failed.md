最让新手困惑的故障莫过于在 [Clash Verge Rev](/clients/clash-verge-rev/) 或 [v2rayN](/clients/v2rayn/) 里点击测速，每个节点都亮着几十毫秒的绿色可用延迟，可一打开浏览器输入海外网址却一直转圈，最后弹出 `ERR_CONNECTION_REFUSED` 或 `ERR_PROXY_CONNECTION_FAILED`。节点测速绿灯已经充分证明服务端线路与出站通道健康，连接不上几乎完全发生在电脑本地，属于流量没有成功送进客户端的监听端口。排查应当按三个优先方向推进，第一优先检查系统代理开关是否真实生效以及本地监听端口有没有被残留进程或加速器抢占，第二优先排查浏览器代理扩展插件、独立安全 DNS 与缓存抢占，第三优先核对防火墙放行规则并区分是全机断连还是特定不走系统代理的桌面软件断连。

## 连接异常现象与排查对照表

遇到本地有测速、浏览器却打不开时，可以先根据报错代码和症状范围直接定位问题层。

| 浏览器或应用报错现象 | 对应根因层 | 验证命令或排查动作 | 推荐处理动作 |
| --- | --- | --- | --- |
| 报错 `ERR_PROXY_CONNECTION_FAILED` | 系统代理指向端口无进程监听 | 检查端口占用与系统代理端口一致性 | 清理旧进程或修改客户端混合端口 |
| 系统代理拨到开启后几秒自动跳回关闭 | 端口冲突或系统管理软件锁死代理 | 用 `netstat` 或 `lsof` 查谁占用了端口 | 结束抢占程序或关掉准入软件冲突项 |
| 仅 Chrome 或 Edge 打不开，另一浏览器正常 | 浏览器扩展插件或内置安全 DNS 冲突 | 按 `Ctrl+Shift+N` 开无痕窗口交叉测试 | 禁用代理切换插件并关闭浏览器安全 DNS |
| 新装机首次运行所有节点均无响应 | 防火墙拦截或核心文件缺出站权限 | 检查 Windows 防火墙允许应用列表 | 将客户端主程序与核心加入双网放行 |
| 浏览器流畅但终端 `git` 或桌面应用卡死 | 应用默认不读取操作系统环境变量 | 查看软件自身代理设置是否填错端口 | 开启 [TUN 虚拟网卡模式](/guides/tun-mode/) 或配置环境变量 |

## 方向一 确认系统代理真实生效并排除端口占用

代理客户端要接管浏览器流量，必须在本地回环地址 `127.0.0.1` 打开一个监听端口（Clash 系常见为 `7897` 或 `7890`，v2rayN 常见为 `10808` 与 `10809`），同时向操作系统注册系统代理。这两个环节只要断开一个，浏览器就走不进代理。

### 核对系统代理开关与系统设置一致性

回到客户端主界面，很多人看到底部状态栏显示运行中就以为万事大吉，其实右侧的系统代理（System Proxy）开关还处于关闭状态。在未开启 TUN 模式的前提下，系统代理不打开，常规浏览器就会直接直连海外网站从而被阻断超时。

如果把系统代理开关打开后没过几秒又自动弹回关闭，或者浏览器立刻报错 `ERR_PROXY_CONNECTION_FAILED`，说明操作系统当前记录的代理端口和客户端正在监听的端口不一致，或者客户端想绑定的端口已经被其他软件提前占死了。

### 使用命令行精准查杀占用端口的冲突进程

Windows 上最常引发端口抢占的元凶有两个，一是之前旧版 [Clash Verge](/clients/clash-verge/)、v2rayN 异常崩溃后残留的底层进程依然霸占着 `7890` 或 `7897` 端口，二是电脑里同时开着网游加速器或另一款网络管理软件。

不要肉眼去进程表里大海捞针，直接在终端按端口号查出真正的 PID 和进程名称，再决定结束冲突进程或把当前客户端的混合端口（Mixed Port）改成冷门数值（例如 `17897`）。

```powershell
# Windows PowerShell 查找正在监听 7890 或 7897 端口的进程详细信息
Get-NetTCPConnection -LocalPort 7890,7897,10808 -State Listen -ErrorAction SilentlyContinue | ForEach-Object {
    $proc = Get-Process -Id $_.OwningProcess -ErrorAction SilentlyContinue
    [PSCustomObject]@{ LocalPort = $_.LocalPort; PID = $_.OwningProcess; ProcessName = $proc.ProcessName; Path = $proc.Path }
}

# 查看当前 Windows 系统注册表实际写入的代理开关与服务器端口
Get-ItemProperty "HKCU:\Software\Microsoft\Windows\CurrentVersion\Internet Settings" | Select-Object ProxyEnable, ProxyServer, AutoConfigURL
```

```bash
# macOS 与 Linux 终端核查本地代理端口监听进程以及系统环境变量是否冲突
lsof -iTCP:7890,7897,10808 -sTCP:LISTEN -n -P
env | grep -i proxy
```

如果 `ProxyServer` 输出里写着一个根本不存在的旧端口号，或者 `AutoConfigURL`（PAC 自动配置脚本）还挂着很久以前残留的失效地址，即便你在客户端反复拨动开关也可能被旧脚本覆盖。进入系统网络代理设置把多余的 PAC 脚本地址清空，再重新开启客户端系统代理，流量就能立刻顺畅注入。

## 方向二 排查浏览器代理插件与独立安全 DNS

很多时候操作系统的代理通道已经畅通无阻，但偏偏常用的 Chrome 死活打不开网页，换成 Edge 或系统内置网页视图却加载飞快。这类局部失灵多半源自浏览器内部的接管权打架。

### 停用过时的代理切换扩展插件

如果你过去在浏览器里安装过 SwitchyOmega 等代理扩展，且扩展当前正处于某个固定情景模式下，浏览器就会优先执行扩展指定的那一组旧 IP 与旧端口，完全无视你在客户端里新改的端口号。一旦扩展里填的端口与现在运行的客户端对不上，网页立刻全部报错。最快的排除方法就是按 `Ctrl+Shift+N`（macOS 为 `Cmd+Shift+N`）打开无痕模式测试一次。无痕模式下默认禁用大部分扩展，如果无痕窗口一秒打开海外网站，回到扩展管理页停用或修正那些代理扩展的端口配置即可。

### 关闭浏览器独立的加密安全 DNS

现代主流浏览器经常默认开启自带的 DNS over HTTPS（安全 DNS）。开启这个功能后，浏览器在向系统代理发起转发前，可能会先自己用浏览器通道向公共加密 DNS 发起域名解析请求，遇到特定网络环境很容易直接卡在查询阶段或收到干扰结果。打开浏览器设置的隐私与安全页面，暂时把使用安全 DNS 关掉，将域名解析统一交还给本地代理客户端处理。关于客户端侧解析机制与浏览器之间的配合方式，可进一步阅读 [DNS 设置完整指南](/guides/dns-settings/)。

## 方向三 核对防火墙放行与区分非系统代理应用

当监听端口和浏览器设置都干净无误，最后一步就是核查操作系统安全拦截以及确认特定应用究竟支不支持系统代理。

### 放行客户端与核心程序的出站权限

首次在全新设备上启动代理软件时，Windows Defender 防火墙会弹出询问是否允许该程序在专用网络和公用网络通信的提示框。如果当时随手点了取消，或者电脑里安装着规则较严的第三方安全管家、企业终端管控客户端，底层核心（`mihomo`、`xray` 或 `sing-box`）向外发起的出站握手包会被系统防火墙直接丢弃。打开 Windows 防火墙的允许应用通过防火墙列表，确认不仅客户端前端界面被放行，连同内核可执行文件也在专用与公用网络处于勾选允许状态。

如果手头暂时连不上任何页面，也可以先用最直接的 `curl` 命令测试究竟是本地端口不通，还是代理通道本身有异常。

```bash
# 1. 不走代理测试本地连通，确认本机基础宽带没断
curl -I --max-time 5 https://www.baidu.com

# 2. 显式指定客户端本地混合端口发起带详细日志的请求，观察卡在本地握手还是远端超时
curl -v -x http://127.0.0.1:7897 --max-time 10 https://cp.cloudflare.com/generate_204
```

如果第二条命令立刻回显 `Connected to 127.0.0.1 port 7897` 并顺利返回 `204 No Content`，说明本地端口监听和外网代理链路已经百分之百健康，问题纯粹是刚才某个浏览器插件或系统设置没有走这个端口；反之若提示 `Connection refused`，则证明端口根本没有听起来，回到方向一继续检查内核进程是否正常启动。

### 区分本地全面断连与特定桌面软件不走代理

不少开发或办公用户会遇到另一种错觉，Chrome 刷视频顺滑无比，偏偏终端里的 `git`、`npm`、`curl`，或者 Telegram 桌面版与某些海外工具客户端一直转圈连不上，便以为是节点挂了。

其实绝大多数命令行工具与部分桌面程序压根不读取 Windows 或 macOS 的系统代理设置。对于这类特定应用失灵，有两个标准解法。要么在这些软件自己的网络设置里手动填入本地代理端口，或者在终端临时注入代理环境变量；要么直接在客户端里开启 [TUN 虚拟网卡模式](/guides/tun-mode/)，在操作系统底层直接创建一张虚拟网卡接管全机所有进程流量。手机端无论是 Android 还是 iPhone，如果开关点亮却全网断连，也务必进系统设置确认是否同时挂载了公司内网 VPN 或其他本地过滤工具，避免配置文件互相顶掉。如果排除了端口与软件接管后依然报错域名无法解析，下一步请转到 [DNS 错误排查](/troubleshooting/dns-error/) 处理，或者参考 [客户端安全与异常排查](/risks/operational-issues/) 核验是否存在外部环境影响。

## 常见问题解答

### 客户端测速明明有几百毫秒绿色延迟，为什么浏览器还是打不开任何国外网站

测速正常证明设备到机场节点的出站通道本身畅通，浏览器打不开网页九成源于本地流量没有正确送进代理软件。最常见的原因包括系统代理开关忘记打开、旧客户端残留进程占用了当前端口、以及浏览器里的 SwitchyOmega 等代理扩展抢占了配置。用 `curl -v -x` 显式走本地端口测试一次就能马上分清界限。

### 为什么我按下了系统代理开关，切到别的页面再看，它又自动关掉了

在 Windows 上通常是因为同机运行着另一个强制改写代理注册表的程序（例如安全管家、企业准入客户端或另一款网游加速器），或者当前配置的 `7890` 与 `7897` 端口已经被残留核心占死无法监听。清理残留后台进程并将客户端混合端口修改为冷门端口通常即可解决。

### 只有某一个特定软件（比如命令行终端或桌面通信工具）连不上，浏览器完全正常，算故障吗

这不算全面网络故障，而是这些独立应用默认不读取操作系统的系统代理设置。只需在该软件的网络代理选项里手动填入本地代理端口，或者直接在 [Clash Verge Rev](/clients/clash-verge-rev/) 中开启 TUN 虚拟网卡模式就能一次性接管全部软件流量。

### Android 端使用 v2rayNG 开启连接后浏览器依然打不开网页怎么排查

首先确保手机没有同时开启省电模式把后台核心强行休眠，其次检查系统 VPN 列表是否被其他应用顶掉，还要确认当前并非误将 Clash YAML 订阅填进了 [v2rayNG](/clients/v2rayng/) 导致规则失效或节点为空。在软件日志页查看是否有具体的连接报错信息，能快速判断卡在本地还是节点端。
