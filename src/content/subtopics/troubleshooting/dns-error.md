在各类代理疑难杂症中，DNS 错误往往最具有迷惑性。节点延迟一片绿色、客户端图标也稳稳亮着，实际使用时却频频出现网页长时间转圈白屏、弹出 `DNS_PROBE_FINISHED_NXDOMAIN`、关掉软件后连国内网站也彻底瘫痪，甚至公司内网与家庭 NAS 一并失联。遇到这类 DNS 错误，按三个优先方向顺着查就能快速收口，第一优先检查本机网卡 DNS 与系统缓存是否残留了软件强退留下的 `127.0.0.1` 回环指向或 `198.18.x.x` Fake-IP 假地址，第二优先核对配置文件的国内外分流 DNS（`nameserver` 与 `fallback`）以及内网过滤清单 `fake-ip-filter` 是否漏配，第三优先关闭浏览器自带的独立安全 DNS 并排查半残缺双栈环境下的 IPv6 解析抢占。

## DNS 故障现象与根因定位对照表

不同症状对应的解析环节完全不同，先根据现象和命令行探测结果定位是本机残留、内网拦截还是上游解析错位。

| DNS 故障现象 | 对应根因层 | 验证命令或排查动作 | 推荐解决方式 |
| --- | --- | --- | --- |
| 退出代理软件后全机网页打不开，微信却正常 | 网卡 DNS 残留 `127.0.0.1` 或 Fake-IP 缓存 | `nslookup` 查看解析结果是否仍为 `198.18.x.x` | 还原物理网卡自动获取 DNS 并清理系统缓存 |
| 开代理后国内网站变慢或跳去海外服务器 | 国内域名被送给境外 DNS 解析 | 对比直连与代理下同一国内域名返回的 IP 归属 | 恢复直连 DNS 为国内可信解析组并停用乱改覆写 |
| 无法访问公司内网域名、校园网或局域网 NAS | 私有后缀未加入 `fake-ip-filter` 跳过清单 | 用 `dig` 或 `nslookup` 查内网域名是否被劫持 | 将内网后缀写进过滤清单或切换为 Redir-Host |
| 仅浏览器报错但命令行解析一切正常 | 浏览器安全 DNS 与系统客户端互相抢占 | 无痕模式及关闭浏览器加密 DNS 后交叉重试 | 关闭浏览器自带安全 DNS 开关及调整 IPv6 |

## 方向一 清理软件强退残留与 Fake-IP 本地缓存

很多用户习惯在任务管理器里直接强杀客户端，或者遇到电脑异常断电重启，重新开机后往往发现即时聊天工具还能收发消息，但所有浏览器网页一律报错找不到服务器。这是因为代理软件在运行期间修改了网卡配置或写入了虚拟 IP 映射，强制退出时没来得及执行善后恢复。

### 清除操作系统内残留的 198.18 假地址缓存

在启用了 [Fake-IP 模式](/guides/dns-settings/) 运行期间，内核为了加快分流响应，会向浏览器和操作系统返回一个位于 `198.18.0.0/16` 保留网段的虚假映射地址。软件正常退出时会自动清理接管状态，但一旦崩溃强退，操作系统 DNS 缓存和浏览器连接池里还死死记着这些假地址。离开代理软件后，本地宽带路由器根本不知道如何路由 `198.18.x.x`，网页自然立刻瘫痪。

最标准的清理办法是打开系统终端执行刷新缓存命令，并配合一次诊断查询确认返回的已经变回真实公网地址。

```powershell
# Windows 命令行清空本地 DNS 解析缓存并核查物理网卡当前的 DNS 指向
ipconfig /flushdns
Get-DnsClientServerAddress -AddressFamily IPv4 | Where-Object { $_.ServerAddresses } | Format-Table InterfaceAlias, ServerAddresses

# 验证常见域名是否已脱离 198.18.x.x 假地址恢复真实解析
nslookup www.baidu.com
```

```bash
# macOS 清空系统级 DNS 缓存并重启解析守护进程
sudo dscacheutil -flushcache && sudo killall -HUP mDNSResponder

# Linux（systemd-resolved 架构）清空缓存并查看当前活动 DNS 服务器
sudo resolvectl flush-caches && resolvectl status
```

### 还原被 TUN 模式改写的物理网卡 DNS 设置

部分开启了虚拟网卡模式的客户端会把当前 Wi-Fi 或有线网卡的 IPv4 首选 DNS 服务器直接改写成 `127.0.0.1` 或特定的虚拟环回地址。如果运行 `Get-DnsClientServerAddress` 后看到你的真实网卡下面还写着 `127.0.0.1`，而代理软件此刻已经关掉了，系统就会把所有解析请求丢进黑洞。

进入 Windows 网络和共享中心更改适配器设置，右键正在联网的网卡属性打开 IPv4 协议设置，把下方的 DNS 服务器重新改回自动获得 DNS 服务器地址并保存。同时检查系统代理界面有没有残留的手动代理服务器开关，一并关掉后刷新网页即可立即恢复。

## 方向二 修正国内外域名分流解析与内网过滤规则

解决了断网残留后，另一种高频困扰是能上网，但要么国内常用站点慢得像蜗牛，要么开启代理后连家里路由器管理页、局域网 NAS 或办公 OA 系统都全部失灵。

### 避免国内域名走境外 DNS 引发的线路绕行

如果你开启了 [Clash Verge Rev](/clients/clash-verge-rev/) 之后，发现国内购物网站图片半天刷不出来，或者访问国内常用音视频服务却被导向了海外节点，问题通常出在配置文件的 `nameserver` 分组错乱。

当你的国内域名被错误交给 `8.8.8.8` 或 `1.1.1.1` 这类海外公共 DNS 解析时，远端解析服务器看不见你真实的国内宽带省份与运营商信息，只能给你返回一个跨国或极远边缘机房的服务器 IP。哪怕你分流规则写得再准，只要拿到的目标 IP 本身落在了境外，后续所有数据包依然要跨海绕行一圈。

排查时应当检查订阅自带配置或自定义覆写脚本，确保基础 `nameserver`（或直连解析规则组）配置的是国内快速可信解析地址（例如 `223.5.5.5`、`119.29.29.29` 或对应加密 DoH），把海外加密 DNS 严格限定在 `fallback` 或匹配境外域名清单的 `nameserver-policy` 中。很多用户因为盲目套用了网上找来的精简覆写脚本，反而把机场原本调校好的 DNS 分流拆坏了，暂时关掉自定义覆写脚本恢复原厂订阅配置，往往马上就能测出明显提速。

### 解决公司内网域名与 NAS 私有地址失联

对于在企业内网办公、连接校园网认证页面或访问家庭内网存储设备的用户，开启代理（尤其是开启了 [TUN 虚拟网卡模式](/guides/tun-mode/) 配合 Fake-IP）时，经常碰上诸如 `oa.company.local` 或 `nas.lan` 等私有地址完全打不开的情况。

原因在于通用分流规则主要针对公网常见网站编写，客户端根本不知道你们单位或家里自己定义的内网后缀。在默认 Fake-IP 机制下，内核直接给内网域名分配了一个 `198.18.x.x` 的虚拟地址并试图送往代理隧道，远程节点服务器当然找不到你的公司内网。想要彻底避开这个冲突，可以直接对配置做两项微调之一。

1. 在配置文件的 `dns.fake-ip-filter` 过滤列表中，通过覆写规则把常用的私有后缀（例如 `*.lan`、`*.local`、`*.home.arpa` 以及具体的公司内部域名后缀）追加进去，命令内核遇到这类请求直接跳过 Fake-IP 映射并交给本地路由器解析。
2. 如果内网子域名非常零散难以穷举，或者你在 [v2rayNG](/clients/v2rayng/) 等移动端也遇到了相似冲突，可以直接在桌面端把 `enhanced-mode` 从 Fake-IP 切换为 **Redir-Host 模式**，让内核老老实实向本地请求真实 IP。

```bash
# 使用 dig 命令对照测试本地网关 DNS 与代理监听端口的解析差异（排查内网或公网解析劫持）
dig @127.0.0.1 -p 1053 oa.example.local +short

# Linux / macOS 排查本地是否还残留了多个监听 53 端口的 DNS 服务冲突
sudo lsof -i :53 -n -P
```

如果在终端看到除了当前使用的 Mihomo 或 sing-box 之外，还有其他旧代理、AdGuard 或 `dnsmasq` 进程在抢占本地 `53` 或 `1053` 端口，先把冲突服务关闭，否则无论怎么改规则都不会生效。

## 方向三 处理浏览器安全 DNS 与残缺 IPv6 抢占

有时客户端配置文件完全标准，用命令行 `nslookup` 和 `dig` 查询的结果也全部正确无误，可偏偏打开 Chrome 或 Edge 时依然报域名解析错误或出现 DNS 泄漏，此时必须把视线转向浏览器独立开关和本地 IPv6 双栈环境。

### 关掉浏览器自带的独立安全 DNS

现代桌面浏览器经常默认开启自己的 DoH（通过 HTTPS 的 DNS）开关。如果浏览器自己越过操作系统的网络接口向外强行发起加密查询，不仅绕开了客户端内置的国内外智能分流，在部分受限宽带下还会直接导致查询请求超时卡死。进入浏览器设置的隐私与安全菜单，把使用安全 DNS 的开关拨至关闭状态，让所有网页域名查询乖乖交给本地代理客户端接管。

### 排查半残缺 IPv6 环境下引发的解析阻塞

国内不少家庭宽带或校园网虽然向终端下发了 IPv6 地址和优先级极高的运营商 IPv6 DNS，但部分路由转发或境外机场节点对 IPv6 链路的支持并不完整。当系统优先向高权重的 IPv6 DNS 发起 `AAAA` 记录查询时，如果代理客户端的隧道只转发 IPv4 数据或者上游节点拒绝 IPv6 出口，浏览器就会陷入长达十几秒的等待甚至直接报连接重置。

在客户端设置中尝试暂时关闭 IPv6 开关（或者在操作系统网卡属性中取消 `Internet 协议版本 6` 的勾选测试一次），如果关闭后网页加载立刻从几秒卡顿变成瞬间秒开，就说明问题完全出在双栈解析冲突上。对于反复修改 DNS 仍然大面积报错的用户，也建议进一步结合 [节点超时排查](/troubleshooting/node-timeout/) 与 [运营异常识别](/risks/operational-issues/) 核查是不是服务端节点入口本身已经下线。

## 常见问题解答

### 为什么我把代理软件关掉之后，电脑连国内网站（比如百度、B站）也全部打不开了

这通常是由配置或缓存残留引起的，一是客户端开启 TUN 模式时把物理网卡的 DNS 改成了 `127.0.0.1`，崩溃或强制退出后没来得及改回自动获取；二是 Fake-IP 模式在系统内存里遗留了指向 `198.18.x.x` 的假地址缓存。把网卡 IPv4 DNS 恢复为自动获取，并在终端执行 `ipconfig /flushdns`（macOS 用 `killall -HUP mDNSResponder`）清空缓存即可立刻恢复。

### 为什么开了代理客户端，公司的内网域名、NAS 局域网地址或校园网登录页就打不开了

因为通用分流规则不包含私有内网后缀，在 Fake-IP 模式下内核会把内网域名同样映射为虚假的 `198.18.x.x` 地址并试图交给远程代理通道，导致局域网本地服务器彻底无法寻址。把公司域名后缀和 `*.local`、`*.lan` 加入配置文件的 `fake-ip-filter` 跳过名单，或者将 DNS 增强模式切换成 Redir-Host 即可顺利访问。

### 提示 DNS_PROBE_FINISHED_NXDOMAIN 或 DNS_PROBE_FINISHED_BAD_CONFIG 怎么修

这说明当前网卡配置的 DNS 服务器不可用或者本地解析链路中断。先检查系统网络适配器设置里是否还留着失效的 `127.0.0.1` 或错误手动地址，将其改回自动获取；同时检查本地代理软件自身有没有正常启动监听，以及浏览器是否开启了互相冲突的安全 DNS 选项。

### 使用 Fake-IP 模式和 Redir-Host 模式到底有什么区别，日常怎么选

在 [DNS 设置完整指南](/guides/dns-settings/) 中有详细机制拆解，简而言之，Fake-IP 跳过真实请求先返回虚拟地址，连接触发极快且适合绝大多数桌面和移动端日常浏览；而 Redir-Host 会向真实上游发出查询并保留真实 IP，更适合内网域名复杂、经常连公司 OA 或需要精准按真实 IP 规则分流的场景。
