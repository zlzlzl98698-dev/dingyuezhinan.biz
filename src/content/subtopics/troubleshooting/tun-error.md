正常情况下开启 [TUN 虚拟网卡模式](/guides/tun-mode/) 后，电脑上的命令行终端和各类不支持系统代理的应用都能顺畅分流。但因为 TUN 模式涉及操作系统底层的虚拟网络适配器驱动与系统路由表修改，一旦系统环境存在权限限制、安全软件拦截或者多款网络工具并存，就很容易报错开关弹回、虚拟网卡起不来甚至开启后立刻全机断网。

## Windows 下常见 TUN 报错与逐项修复

Windows 是 TUN 故障最多发的平台，绝大多数报错集中在服务提权、驱动残留和软件冲突三件事上。

### 1. 服务模式（Service Mode）安装失败或状态显示异常

像 [Clash Verge Rev](/clients/clash-verge-rev/) 这类采用独立后台服务提权的客户端，首次使用 TUN 必须先成功安装并运行 Service Mode，很多用户卡在这一步。

1. **必须使用管理员权限运行主程序或服务安装**：彻底右键托盘退出当前客户端，然后右键桌面的客户端快捷方式，点击“以管理员身份运行”。进入设置页面，先点击卸载已残留的旧服务（如果按钮亮着），再重新点击安装服务并点开启动。服务正常变成绿色后，一般以后正常权限启动主软件就能直接拨动 TUN 开关了。
2. **确保安装目录为纯英文且未触发安全拦截**：部分用户的用户名是中文，而安装服务或提取内置 `wintun.dll` 驱动文件时容易在中文路径或包含空格的目录报错。同时，360、火绒、腾讯电脑管家等国产安全软件以及企业部署的终端管控软件，经常把“注册未知系统服务”当成高危恶意行为直接拦截。在确认官方安装包无误的前提下，先将软件目录加入安全防护白名单再重试安装服务。

### 2. 老旧 Wintun 驱动残留与虚拟网卡打架

如果之前你电脑上装过老版本 Clash for Windows、其他 VPN 客户端或者网游加速器，系统的网络适配器列表中可能残留着损坏的 Wintun 网卡驱动或者同名的旧虚拟网卡设备，新客户端想创建同样名称的 `Meta` 或 `sing-box` 虚拟网卡时就会直接报错无法创建接口。

修复方法很干净。先完全关闭当前代理软件，在 Windows 搜索框输入并打开“设备管理器”，展开“网络适配器”列表，仔细找找里面有没有名称带有 `Clash`、`Meta`、`sing-box`、`Wintun` 的残余虚拟网卡图标（注意别误删你的真实无线网卡 Wi-Fi 和有线千兆网卡）。右键那些废弃的虚拟网卡选择“卸载设备”，然后重启电脑再打开新版客户端开启 TUN，系统会自动重新下发并安装一块全新干净的虚拟网卡驱动。

### 3. 开启 TUN 后立刻断网或与加速器/办公 VPN 冲突

如果你一打开 TUN 开关，整个电脑所有网页瞬间失联，关掉开关又恢复，请重点排查两个地方。

第一是 **多虚拟网卡冲突**。切记，代理软件的 TUN 模式、雷神/UU 等游戏加速器的加速模式、以及公司要求连接的企业 SSL VPN，三者全都是在抢占系统最顶层的默认路由出口。任何时候同时开着其中两个，电脑的路由表就会不知道该把包发给谁，最终全部丢失。用公司内网或开游戏加速器前，务必先关掉代理软件的 TUN 模式。

第二是 **开启 TUN 时顺手打开了不匹配的路由堆叠（Stack）**。在高级配置里，Mihomo 核心的 TUN 通常支持 `system`、`gvisor` 和 `mixed` 三种网络协议栈。如果在你的 Windows 上默认模式下出现网页打不开但延迟正常，可以在设置页面的 TUN 高级选项里，把协议栈在 `mixed` 与 `system` 或 `gvisor` 之间切换尝试一次，往往能立刻解决底层驱动握手异常。另外检查是否不小心勾中了“严格路由（Strict Route）”导致国内和局域网路由被一刀切。

## macOS 与 Linux 下的 TUN 异常解决

苹果电脑和 Linux 桌面的虚拟网卡授权机制更加透明直观。

### macOS 报错处理

如果打开 TUN 开关时系统没有弹出密码框直接报错失败，或者每次开机都要反复输入系统密码：

1. 首先确保你没有直接从浏览器下载区或者挂载着的 DMG 镜像盘里直接双击运行客户端，必须把软件完整拖入 `/Applications`（应用程序）文件夹再启动。
2. 尝试打开客户端设置，找找重新授予核心提权（Grant Permissions）的按钮，按提示输入开机密码授权。
3. 苹果系统本身的“网络 -> VPN 与过滤”中如果还开着其他海外商业 VPN 残留的配置描述文件，同样会阻塞新建 `utun` 虚拟接口，将不再使用的旧 VPN 配置文件删除即可。

### Linux 权限配置

Linux 环境下如果点开 TUN 报 `permission denied` 或 `operation not permitted`，原因几乎都是底层的核心文件缺少操作系统网络管理特权。

不要盲目直接用 `sudo` 强行拉起整个图形界面窗口（那会导致桌面环境变量和配置文件归属权混乱）。正确做法是按照对应客户端官方文档，只针对底层的内核可执行文件（例如软件内置目录下的 `mihomo` 或 `sing-box`）执行一次 `sudo setcap cap_net_admin,cap_net_bind_service=+ep 核心文件路径`。授权完毕后，使用普通桌面用户正常启动图形客户端即可直接顺畅打开 TUN 虚拟网卡。

对于只是用来在浏览器看剧和日常查资料的用户，如果折腾完驱动还是与你电脑上的某些特殊财务、安全客户端不兼容，其实没有必要死磕 TUN 模式，维持轻快稳定的常规“系统代理”同样能够满足日常使用。
